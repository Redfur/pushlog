# Расширяемость и этапы развития

## 1. Текущая база (реализовано в репозитории)

- IndexedDB + Zustand: подходы, **каталог типов упражнений** (UUID), **цели по типам**.
- **Главная** (`/`): карточки «сегодня», quick-add с выбором типа, каталог упражнений; **экран дня** (`/day/...`): навигация по датам, прогресс, список подходов, quick-add.
- **Карточка упражнения** и редактирование (`/exercises/*`); статистика общая и по типу (`/stats`, `/stats/exercise/:id`); настройки `/settings` (тема, язык — только русский в UI, таймзона, опасная зона данных).
- Удаление подхода, undo через toasts, обработка ошибок storage (`lastError` в store).
- PWA: `site.webmanifest`, Service Worker и precache через `vite-plugin-pwa` (офлайн после первой загрузки).

**Временно (инфраструктура):** в корне проекта [`.npmrc`](../.npmrc) с `legacy-peer-deps=true` — из‑за рассинхрона peer `vite-plugin-pwa` (ожидает Vite ≤7) и фактического **Vite 8**. Убрать после того, как плагин официально поддержит Vite 8 и `npm install` проходит без этой настройки.

## 2. Улучшение UX

- **Обновление клиента (PWA / Service Worker):** реализовано через `virtual:pwa-register` и toast (Sonner): при готовности новой версии SW — «Обновить» / «Позже», при сборке в CI подставляется `VITE_APP_VERSION` из тега релиза. Опционально дальше: выводить краткий текст изменений из релиза в UI.
- Расширение сценариев undo (единообразие по всем действиям).
- Дальнейшие анимации и skeleton (частично уже есть).
- Оптимизация холодного старта и размера бандла.
- **Многоязычный UI**: дополнительные локали и **активный** выбор языка на экране настроек (сейчас селект языка **задизейблен**, доступна только русская локаль).

Реализация и детали UI: [spec/ui.md](ui.md) (навигация на десктопе, ленивые `/stats` и `/settings`, toasts, гидратация, timezone).

## 3. Геймификация

- Стрик (правила «не пропустить день») и отображение стрика в UI (счётчик уже входит в `Stats`).
- Расширения heatmap (диапазоны, год) при необходимости.
- Достижения (опционально, минимально).

## 4. Backend + sync

- Аккаунт, синхронизация между устройствами.
- Конфликт-резолвинг (например, по `updatedAt`/операционным логам).
- `ApiStorageAdapter` или слой sync поверх существующего store.

## 5. Дальнейшее расширение домена

- Дополнительные единицы учёта: время, вес (вне текущей модели «повторы за подход»).
- Ленивая загрузка истории подходов при очень больших объёмах данных.

## 6. CI/CD

- **CI на каждый push** (любая ветка): workflow запускает `npm run check` (Biome), `npm run knip`, `npm run build` — см. `.github/workflows/ci.yml`.
- **Релизы:** перед тегом заполняется [CHANGELOG.md](../CHANGELOG.md) (формат Keep a Changelog; секция `## [X.Y.Z]` без префикса `v`). Тег и push выполняет скрипт **`npm run release -- X.Y.Z`** ([scripts/release.sh](../scripts/release.sh)): проверки CHANGELOG, `package.json`, git, при необходимости `check`/`knip`, затем `git tag` / `git push`. Альтернатива — вручную `git tag` / `push`. Workflow `.github/workflows/release.yml` по push тега собирает описание из CHANGELOG + список коммитов и создаёт GitHub Release (если ещё не существует).
- **Прод (GitHub Pages):** деплой только при **публикации** GitHub Release — `.github/workflows/deploy-pages.yml` (`release: published`), с теми же гейтами `check`, `knip`, затем сборка; `VITE_APP_VERSION` = имя тега (например `v1.0.0`). Пуш в `main` без релиза прод не обновляет.
