# Термины и концепции

## Set (подход)

Единица учёта: сколько раз выполнено упражнение **за один заход** в конкретный момент времени.

- Связан с **днём** через календарную дату (`dayKey`) и/или метку времени `createdAt`.
- В MVP — отжимания; поле **типа упражнения** (см. ниже) позволяет не смешивать разные дисциплины при расширении.

## DayLog (день)

Логическая группировка подходов за **один календарный день** в заданной timezone.

- Не обязательно отдельная сущность в БД: может вычисляться как фильтр `Set` по `dayKey`.
- Используется для списка «за сегодня», дневной суммы и heatmap в будущем.

## Streak (стрик)

Количество **подряд идущих календарных дней**, в каждый из которых был хотя бы один подход (правила уточняются на этапе геймификации).

- В MVP: **не отображается** в UI; вычисление может быть заготовлено в `computeStreak` для быстрого включения.

## Goal (цель)

Целевое значение (например, повторений **за день** или **за неделю** — в MVP достаточно дневной цели).

- Опциональна: приложение полезно и без цели.
- Хранится отдельно от `Set`; влияет на отображение прогресса.

## ExerciseType (тип упражнения) — задел

Справочник типов: `id`, `name`, `unit` (повторения, время и т.д.).

- MVP: один тип — «Отжимания» с фиксированным `id` (константа в `shared/config` или seed в БД).
- Новые типы не добавляются через UI в MVP; модель `Set` уже содержит `exerciseTypeId`.

## Связи

```
ExerciseType (1) ──< (N) Set
                        │
                        ├── dayKey / createdAt → принадлежность DayLog (виртуально)
                        │
Goal (1) ──────────────┼── сравнивается с агрегатом DayLog (сумма по типу за день)
```

- **Stats** — производная от множества `Set` (и опционально `Goal`): не хранится как первичные данные, кроме кэша в памяти.
