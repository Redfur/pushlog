# Термины и концепции

## Set (подход)

Единица учёта: сколько раз выполнено упражнение **за один заход** в конкретный момент времени; опционально **вес** (кг на подход), если у типа включён трекинг веса.

- Связан с **днём** через календарную дату (`dayKey`) и/или метку времени `createdAt`.
- Поле **типа упражнения** (`exerciseTypeId`, UUID) ссылается на запись в каталоге **ExerciseType** в IndexedDB. В одном логе дня могут быть подходы разных типов.

## DayLog (день)

Логическая группировка подходов за **один календарный день** в заданной timezone.

- Не обязательно отдельная сущность в БД: может вычисляться как фильтр `Set` по `dayKey`.
- Используется для списка «за сегодня», дневной суммы и heatmap в будущем.

## Streak (стрик)

Количество **подряд идущих календарных дней**, в каждый из которых был хотя бы один подход (правила уточняются на этапе геймификации).

- В MVP: **не отображается** в UI; значение входит в агрегат `Stats` (`computeStats` / `computeStreak` в `entities/pushup`).

## Goal (цель)

Целевое значение (например, повторений **за день** или **за неделю** — в MVP достаточно дневной цели).

- Опциональна: приложение полезно и без цели.
- Хранится отдельно от `Set`; влияет на отображение прогресса.

## ExerciseType (тип упражнения)

**Каталог в IndexedDB** (`exerciseTypes`): у каждой записи стабильный UUID (`id`), пользовательское **имя**, отображение значка (`iconDisplay`: lucide или text, `iconKey` / `iconEmojiText`, `nameInitialGlyph`), цвет (`colorKind` / `colorValue`), флаг **`trackWeightInSets`** (ввод веса в кг для каждого подхода — для силовых), опционально **`archivedAt`** (мягкий архив: тип не в селекторах новых подходов, история и статистика сохраняются).

- В UI **не** фильтрует уже записанный лог за день — все типы видны в **DaySetsList**.
- Задаёт тип **новых** подходов через **предпочитаемый тип** (`preferredExerciseTypeId`), персист в **localStorage** (см. `shared/lib/preferred-exercise-type`).
- Пресеты только для **иконок и цветов** — в `shared/config/exercise-type-presets`; сами упражнения создаёт пользователь (`/exercises/new`), не статический конфиг.

## Связи

```
ExerciseType (1) ──< (N) Set
                        │
                        ├── dayKey / createdAt → принадлежность DayLog (виртуально)
                        │
Goal (N по типам) ─────┼── сравнивается с суммой `reps` за день для того же `exerciseTypeId`
```

- **Stats** — производная от множества `Set` (и опционально `Goal`): не хранится как первичные данные, кроме кэша в памяти.
