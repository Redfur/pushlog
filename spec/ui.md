# UI спецификация

## Навигация (MVP)

- Четыре пункта: **Главная** (`/`), **День** (`/day/today` — календарь и лог за выбранный день), **Статистика**, **Настройки**.
- Переключение: **нижняя навигация** на узких экранах (`lg` ниже); на **`lg` и шире** — фиксированная **левая колонка** (~64 tailwind units), нижняя панель скрыта. Контент: `mx-auto`, `max-w-3xl` (статистика до `max-w-4xl`), отступы `px-4 sm:px-6`.
- **Главная** `/`: сводка за сегодня (**сетка карточек** по образцу блока totals на статистике: общая карточка + по одной на активный тип), быстрый ввод, список активных типов с переходом в карточку упражнения.
- Пункт **«Главная»** в навигации считается активным и для путей **`/exercises/*`** (каталог, карточка, создание, редактирование).
- **Маршруты дня:** `/day/today`, `/day/yesterday`, `/day/YYYY-MM-DD` — `widgets/main-screen` (**DayScreen**).
- **Карточка упражнения (обзор):** `/exercises/:exerciseId` (UUID) — ленивый чанк; в шапке кнопка «назад» на главную (**PageHeaderBackLink**), метрики карточками, архив/вернуть, **полное удаление** типа (подтверждение в `AlertDialog`, удаление подходов и цели в IndexedDB); меню «ещё» (`DropdownMenu`) с пунктами **«Подробная статистика»** → `/stats/exercise/:id` и **«Редактировать»** → `/exercises/:id/edit`.
- **Создание:** `/exercises/new` — отдельный маршрут (тот же ленивый чанк), полная форма сразу.
- **Редактирование:** `/exercises/:exerciseId/edit` — ленивый чанк; одна форма: имя/иконка/цвет (**ExerciseTypeEditorFields**) и **дневная цель** (**ExerciseDailyGoalEditor** в `features/set-daily-goal`); одна кнопка **«Сохранить»** сохраняет тип и цель; после успеха — переход на карточку `/exercises/:id` и toast.
- **Статистика:** `/stats`, `/stats/exercise/:exerciseId` — ленивые чанки + `Suspense`.
- **Настройки:** `/settings` — ленивый чанк. Старый путь `/settings/exercises` редиректит на `/`.

## Шапка экрана (`shared/layout`)

Тело экрана под `AppShell` оборачивают в **ScreenBody** (`variant`: `page` с `gap` `compact` / `comfortable`, `skeleton` без липкой первой строки, `skeletonSticky` если первым идёт **PageHeaderSkeleton**). Так не дублируются `pt-0 pb-4` и отступы скелетонов на каждой странице.

Единый компонент **PageHeader**: один `h1` на страницу, **прилипает к верху** при прокрутке (`sticky top-0`), полупрозрачный фон и `backdrop-blur`, нижняя граница; классы поверхности — **STICKY_PAGE_HEADER_SURFACE** (горизонталь как у контейнера `AppShell`, **верхний отступ внутри шапки** `pt-4 lg:pt-6`, чтобы не дублировать `py-4` страницы и убрать скачок при `sticky`). У обёртки маршрута в `AppShell` сверху на `lg` отступ снят (`lg:pt-0`), нижний `lg:pb-2` сохранён. Опционально слоты **leading** (кнопка «назад» — **PageHeaderBackLink**, `ChevronLeft` без рамки: `ghost` + приглушённый цвет, в отличие от `outline` у стрелок **DayNavigation**), **media**, **description**, **actions** (кнопки или **DropdownMenu** с триггером `Button variant="outline" size="icon"`). Переводы подписей и `aria-label` задаются в NS экрана.

Для состояний загрузки — **PageHeaderSkeleton** с той же прилипающей поверхностью (`showMedia` при необходимости).

На экране дня **DayNavigation** передаётся в **PageHeader** как **`centerContent`** (тот же липкий блок и отступы, что на остальных экранах). Заголовок для a11y — отдельный `sr-only` `h1` в **DayScreen**.

Используется на главной, настройках, сводной и детальной статистике по упражнению, карточке упражнения (в т.ч. создание), редактировании типа. **Исключение:** экран дня (`/day/:dayKey`) — верхняя зона остаётся **DayNavigation** (другой UX), для доступности сохраняется скрытый `h1` в **DayScreen**.

## Навигация по дням (DayNavigation)

| Аспект | Описание |
|--------|----------|
| Ответственность | Переход к предыдущему/следующему дню; выбор даты кликом по **заголовку даты** — Popover + календарь shadcn (`Calendar` + `react-day-picker`), чтобы одинаково работало на десктопе и в тач-интерфейсе. |
| Календарь | У дат, в которые есть хотя бы одна запись (по `dayKey` в store), под числом показывается **точка**; пустые дни без точки. |
| Поведение | Следующий день недоступен, если он позже сегодня. Переход на главную — пункт «Главная»; на сегодняшний день в календаре — пункт «День». |

## Главная (`/`)

Виджет `widgets/home-screen` (**HomeScreen**): секция **HomeTodayStatsCards** (сетка карточек «Сегодня»), в шапке иконка календаря → `/day/today` (`aria-label` / `title` — текст «День и календарь»), блок **ExerciseQuickAddBlock** (`widgets/main-screen`): ряд кнопок-иконок по активным типам (синхрон с `preferredExerciseTypeId`) + **QuickAddPanel** с заголовком «Быстро добавить: {имя}» для **сегодняшнего** `dayKey`, список активных упражнений (ссылки в `/exercises/:id`), кнопка «Добавить упражнение» → `/exercises/new`.

## Экран дня (`/day/:dayKey`)

Состав: **DayNavigation**, **DayProgress**, карточки **тоннажа** (**DayTonnageCards**: выбранный день и скользящие 7/30 дней), **ExerciseQuickAddBlock** (табы типа + **QuickAddPanel**), **DaySetsList** (`widgets/main-screen`, **DayScreen**).

### Выбор типа для записи (`features/select-exercise`)

| Аспект | Описание |
|--------|----------|
| Ответственность | Задать `preferredExerciseTypeId` для новых подходов и для «повторить последний»; значение в `localStorage`. |
| Поведение | **Не** фильтрует список подходов и статистику — все типы видны в общем логе. В списке только **активные** типы из store. |

### QuickAddPanel

| Аспект | Описание |
|--------|----------|
| Ответственность | Минимум шагов для добавления подхода: ввод числа повторений и подтверждение; при **`trackWeightInSets`** у выбранного типа — также поле **веса (кг)**. |
| Содержимое | **Поле повторений** (цифры) и кнопка отправки; при трекинге веса — второе поле (десятичный вес, кг). Кнопки **−1**, **+1**, **+5**, **+10** меняют **черновик** повторов (не создают подход сразу). Отправка формы вызывает `addReps(reps)` или `addReps(reps, weightKg)`. |
| Поведение | Успешное добавление — **тост с «Отменить»** (удаление последнего добавленного id); поля повторов и веса **не очищаются** после отправки. Черновики по **`exerciseTypeId`** персистятся в **localStorage** (`pushlog.quickAddDraft.v1`), подгружаются при смене типа; очищаются при сбросе localStorage в настройках. Тип и `dayKey` — из контекста (**preferred** + `dayKey` экрана). Если **нет активных типов** — подсказка со ссылкой на `/exercises/new` (в родительском **ExerciseQuickAddBlock**). Для **будущего дня** — подсказка `futureDayReadOnly`. Защита от двойных тапов — в `useAddSet` (интервал ~220 ms). |
| Повтор последнего | В текущей версии **нет** отдельной кнопки; при необходимости — добавить в `useAddSet` / UI по правилам из прошлых версий spec (последний подход за день для выбранного типа). |

### Список подходов за день (DaySetsList)

| Аспект | Описание |
|--------|----------|
| Ответственность | Показать **все** `Set` за текущий `dayKey` (все `exerciseTypeId`). |
| Отображение | Иконка и короткое название типа; число повторений; при наличии веса — «× {вес} кг»; если тип с трекингом веса, а вес в записи отсутствует (старые данные) — прочерк; время (локальное). |
| Поведение | Кнопка «удалить» на строке → `removeSet(id)`; после удаления — **тост «Отменить»** (`restoreSet`). |
| Пустое состояние | Короткий текст + быстрые кнопки в фокусе. |

### Дневной прогресс (DayProgress)

| Аспект | Описание |
|--------|----------|
| Ответственность | По каждому типу, у которого за день есть повторения **или** задана дневная цель: строка с суммой по типу; при цели — дробь и **Progress** только для этого типа. Отдельно — число **записей** подходов за день (строки в логе). |
| Поведение | Не смешивать повторения разных упражнений в одну цель без подписи. Синхронно с store. |

## Экран настроек

Маршрут `/settings`, виджет `widgets/settings-screen`.

| Блок | Описание |
|------|----------|
| Тема | Режимы: системная (по умолчанию), светлая, тёмная; хранение в `localStorage`, класс `dark` на `html`. |
| Язык | Селект **задизейблен**: в интерфейсе зафиксирована русская локаль; дополнительные языки и активный выбор — в планах ([roadmap.md](roadmap.md) §2). |
| Регион и цели | Текст со ссылкой на **главную** (каталог упражнений); подсказка, что **дневная цель** задаётся при **создании** или **редактировании** упражнения (`/exercises/new`, `/exercises/:id/edit`); часовой пояс (`features/set-timezone`). |
| Данные | Отдельные действия: очистка IndexedDB (подходы, типы, цели), сброс `localStorage` (тема, таймзона, предпочитаемый тип упражнения — см. `shared/lib/client-storage-keys`), «очистить всё» с перезагрузкой страницы. Подтверждение через `AlertDialog`. |
| О приложении | Внизу: текст **«Версия …»** (из сборки: `VITE_APP_VERSION` в CI или `version` в `package.json` локально) и ссылка на репозиторий (`VITE_REPO_URL` в CI или `repository` в `package.json`). |

### Дневная цель (детали)

| Аспект | Описание |
|--------|----------|
| Ответственность | Ввод целевого числа повторений в день **для конкретного типа**; хранение в `meta` IndexedDB (`goalsByExerciseTypeId`); сброс цели (пустое поле + сохранение). Основной UX — **ExerciseDailyGoalEditor** на **`/exercises/new`** (необязательно) и **`/exercises/:id/edit`** в одной форме с типом (для архивного типа — только подсказка без поля). Массовый выбор типа в настройках не используется в MVP. |
| Поведение | Прогресс к цели — в **DayProgress** отдельно по каждому типу с целью. |

## Карточка упражнения (обзор `/exercises/:exerciseId`, создание `/exercises/new`, редактирование `/exercises/:exerciseId/edit`)

| Аспект | Описание |
|--------|----------|
| Обзор (UUID) | Заголовок с иконкой/цветом; карточки метрик **сегодня** (подходы, повторы) и **за всё время** (повторы, подходы, дней с записями); **В архив** / **Вернуть**; кнопки «Подробная статистика» и «Редактировать». |
| Создание (`/exercises/new`) | Форма **ExerciseTypeEditorFields** + **ExerciseDailyGoalEditor** (цель необязательна); по умолчанию иконка Lucide **chevrons-up**; сохранение типа и при необходимости цели через store; после создания — редирект на `/exercises/:uuid`. |
| Редактирование | **ExerciseTypeEditorFields** + **ExerciseDailyGoalEditor**; одна отправка формы; кнопка «К упражнению» → обзор. |
| Значок типа | В IndexedDB: `iconDisplay` — **lucide** (выбор из пресета Lucide) или **text** (поле ввода emoji/символов без пикера). При пустом поле emoji сохраняется и показывается **первая графема названия** (`nameInitialGlyph`), обновляется при сохранении формы. Отображение: **ExerciseTypeIcon** по полям типа. |
| Поведение | `putExerciseType` / обновление типа в IndexedDB. |

## Экран статистики (`/stats`)

Состав: компактный список **ссылок по всем типам** из каталога (включая архивные) → `/stats/exercise/:id`; блок **общей сводки**; карточки **тоннажа** (сегодня / 7 / 30 дней) и график **дневного тоннажа** (7/30 дней); обзорный график повторов/подходов; heatmap по всем типам (`widgets/stats`).

### Список «По упражнениям»

| Аспект | Описание |
|--------|----------|
| Ответственность | Строки-ссылки: имя, иконка, метка «в архиве» при необходимости; детальные метрики и графики только на странице типа. |

### Блок totals

| Аспект | Описание |
|--------|----------|
| Ответственность | Сводка по **всем** подходам: сумма повторений (с подсказкой о смешении), всего подходов, дней с любой активностью, среднее за активный день. |
| Поведение | `computeStats` по полному массиву `sets`. |

### Блок averages

| Аспект | Описание |
|--------|----------|
| Ответственность | Среднее повторений на **активный** день; при отсутствии дней — «—». |
| Поведение | Не делить на календарные дни без записей. |

### Best day

| Аспект | Описание |
|--------|----------|
| Ответственность | День с максимальной **суммой повторений по всем типам**; подпись, что это смешанный объём. |
| Поведение | При равенстве — более ранняя дата (`computeStats`). |

### Графики динамики (сводка)

| Аспект | Описание |
|--------|----------|
| Ответственность | За **7** или **30** дней: **столбцы** суммарных повторений по дням (все типы); **линия** числа подходов за день. |
| Поведение | Подсказка, что столбец — сумма по всем упражнениям за день. |

## Статистика по одному типу (`/stats/exercise/:exerciseId`)

| Аспект | Описание |
|--------|----------|
| Ответственность | Заголовок с именем/иконкой/цветом типа; карточки `computeStatsForExerciseType`; при **`trackWeightInSets`** — карточка максимального веса за всё время, карточки и график **тоннажа** (сегодня / 7 / 30 дней и динамика по дням), график **максимального веса по дням** (7/30 дней); тот же виджет тренда повторов/подходов на **отфильтрованных** `sets`; heatmap с фильтром по одному `exerciseTypeId`. |
| Поведение | Доступно и для **архивных** типов; неверный/отсутствующий UUID — сообщение и ссылка назад на `/stats`. |

### Heatmap

| Аспект | Описание |
|--------|----------|
| Ответственность | Сетка «недели × дни недели» (26 недель); интенсивность ячейки — **сумма** `reps` за день по **всем** типам; в tooltip при нескольких типах — разбивка по типам. |
| Поведение | Ячейки будущих дней без данных; легенда «меньше / больше». |

## Гидрация и первый кадр

- Пока данные из IndexedDB не загружены, основной контент заменён **скелетонами**, близкими к реальной сетке карточек (день и статистика), чтобы уменьшить layout shift.
- После `hydrated === true` контент слегка **проявляется** (например `fade-in` / лёгкий `translate`), без обязательной motion-библиотеки.

## Уведомления (toasts)

- Глобальный **Toaster** (Sonner) в провайдерах приложения; действия «Отменить» после добавления/удаления подхода с ограничением по времени (стандартное поведение библиотеки).

## Переиспользование UI-kit

- Кнопки, карточки, прогресс: `@/components/ui/*` (Button, Card, Progress и т.д.).
- Тема: выбор режима на экране настроек (`widgets/settings-screen`, `shared/lib/theme`: системная / светлая / тёмная) и токены Tailwind.

## i18n

- Все пользовательские строки — через колоцированные `translations.ts` в слайсах + `shared/i18n` для общих меток (отмена, ошибки).
