# Функциональные требования

## User stories

1. Как пользователь, я хочу одним действием записать подход отжиманий (фиксированное число или «как в прошлый раз»), чтобы лог занимал меньше двух секунд от намерения до подтверждения в UI.
2. Как пользователь, я хочу видеть список подходов за сегодня и сумму/прогресс за день, чтобы контролировать объём без калькулятора.
3. Как пользователь, я хочу удалить ошибочно добавленный подход, чтобы данные оставались честными.
4. Как пользователь, я хочу открыть экран статистики и видеть итоги, средние и лучший день, чтобы оценивать динамику.
5. Как пользователь, я хочу пользоваться приложением без сети (PWA), чтобы логировать везде.

## Функциональные требования (MVP)

- **Логирование подхода**: добавление записи с количеством повторений, привязка к «сегодня» в выбранной логике календарного дня (см. edge cases — timezone).
- **Быстрые действия**: кнопки быстрого добавления (+N из пресетов), действие «повторить последний подход» (по типу упражнения по умолчанию — отжимания).
- **Список за день**: отображение подходов за текущий календарный день, порядок по времени добавления (или по `createdAt`).
- **Дневной прогресс**: отображение суммы повторений за день (и при наличии цели — прогресс к цели; минимум — сумма).
- **Статистика**: агрегаты по истории — всего повторений, среднее за день (по дням с записями), лучший день по сумме повторений.
- **Локальное хранение**: персистентность без бэкенда; данные переживают перезапуск приложения.
- **Один тип упражнения в MVP**: отжимания; модель данных допускает `exerciseTypeId` для расширения без миграции схемы «с нуля».

## Non-goals (сейчас не делаем)

- Сервер, аккаунты, синхронизация между устройствами.
- Социальные функции, лидерборды, шаринг.
- Напоминания и push-уведомления (кроме задела под PWA — без реализации сценариев).
- Расширенная геймификация: стрик и heatmap **не в MVP** — только задел в модели/UI-текстах спецификации.
- Импорт/экспорт, интеграции с Health/Google Fit (возможный этап позже).
- Редактирование произвольного количества в прошлом дне (MVP — фокус на «сегодня»; правки прошлого не обязательны).

## Edge cases

| Ситуация | Ожидание |
|----------|----------|
| **Двойные тапы / быстрые клики** | Идемпотентность на уровне UI: debounce или блокировка кнопки на время записи; один пользовательский жест не должен создавать дубликаты без явного намерения. Store принимает последовательные `addSet` — каждый валидный клик создаёт отдельный `Set` с уникальным `id`; защита от случайного double-submit — на стороне feature. |
| **Смена календарного дня (полночь, timezone)** | «Сегодня» вычисляется по одной выбранной стратегии: календарная дата в `Intl`/IANA timezone пользователя (см. `shared` config). При пересечении полночи список и quick-add переключаются на новый день без перезагрузки страницы (подписка на тик или на `visibilitychange`). |
| **Рассинхрон хранилищ** | В MVP единственный источник истины — IndexedDB через `StorageAdapter`. localStorage не используется для доменных данных; если в будущем появится кэш — версионирование схемы и миграции, при конфликте — приоритет БД. |
| **Пустые данные** | Нет подходов: пустой список, дружелюбный empty state, быстрые кнопки доступны. Статистика: нули или «—» для среднего/лучшего дня по правилам в `domain.md`. |
| **Повреждённое/частично прочитанное хранилище** | Ошибка чтения: показать сообщение и возможность сброса/повторной инициализации БД (минимум — лог в консоль + UI error boundary для стора). Запись: retry ограниченно; не блокировать UI дольше целевого времени отклика. |
| **Очень большая история** | Загрузка в store ленивая или по диапазону дат для статистики; главный экран только «сегодня» — O(n) по числу подходов за день (обычно мало). |
