# Функциональные требования

## User stories

1. Как пользователь, я хочу быстро записать подход с **заданным числом повторений** для **выбранного типа упражнения**, чтобы лог занимал меньше двух секунд от намерения до подтверждения в UI.
2. Как пользователь, я хочу видеть сводку за сегодня на главной и при необходимости открыть **экран дня** со списком подходов и прогрессом, чтобы контролировать объём без калькулятора.
3. Как пользователь, я хочу удалить ошибочно добавленный подход (с возможностью отмены через toast), чтобы данные оставались честными.
4. Как пользователь, я хочу вести **несколько видов упражнений** (создание, редактирование, архив), с отдельной целью и статистикой по типу.
5. Как пользователь, я хочу открыть экран статистики и видеть итоги, средние, лучший день, графики по дням и heatmap, чтобы оценивать динамику.
6. Как пользователь, я хочу пользоваться приложением без сети (PWA), чтобы логировать везде.

## Функциональные требования (текущий продукт)

- **Каталог упражнений**: создание (`/exercises/new`), карточка (`/exercises/:id`), редактирование (`/exercises/:id/edit`); типы в IndexedDB, UUID; архив / возврат из архива.
- **Логирование подхода**: добавление записи с количеством повторений, привязка к **выбранному календарному дню** (`dayKey`); быстрый ввод за **сегодня** на главной (`/`), подробный день и календарь — `/day/today` и др. Будущие дни недоступны для записи.
- **Точное число повторений**: ввод числа в **QuickAddPanel** в дополнение к шаговым кнопкам (+1, +5, +10 и т.д. — см. реализацию).
- **Перенос / задним числом**: пользователь может открыть любой **прошедший или сегодняшний** день (стрелки, календарь, URL `/day/YYYY-MM-DD`, `/day/today` или `/day/yesterday`) и добавлять подходы за этот день.
- **Быстрые действия**: пошаговое изменение черновика в поле ввода (−1 / +1 / +5 / +10) и отправка (см. `spec/ui.md`, QuickAddPanel). «Повторить последний» — возможное улучшение UX, сейчас не выведено в UI.
- **Список за день**: на экране дня — все подходы за выбранный `dayKey`, порядок по `createdAt`.
- **Дневной прогресс**: на экране дня — суммы и цели **по каждому типу** отдельно (**DayProgress**); **дневная цель** задаётся при **создании** (`/exercises/new`) и **редактировании** (`/exercises/:id/edit`) через **ExerciseDailyGoalEditor**, не на экране статистики.
- **Статистика**: агрегаты по истории; графики за **7** и **30** дней; **heatmap**; разрез по типам на `/stats/exercise/:id`.
- **Локальное хранение**: персистентность без бэкенда; подходы, типы и цели — **IndexedDB**; предпочтения UI (тема, таймзона, предпочитаемый тип и т.д.) — **localStorage** (см. `shared/lib/client-storage-keys` и `clear-client-storage`).
- **Резервная копия данных**: в `/settings` доступны экспорт JSON и импорт JSON. Импорт проходит валидацию структуры (формат, версия, связи set/goal ↔ exerciseType) и выполняет полную замену доменных данных в IndexedDB после явного подтверждения.

## Non-goals (сейчас не делаем)

- Сервер, аккаунты, синхронизация между устройствами.
- Социальные функции, лидерборды, шаринг.
- Напоминания и push-уведомления (кроме задела под PWA — без реализации сценариев).
- Расширенная геймификация: отображение **стрика** в UI и напоминания — вне текущего объёма (значение стрика может считаться в агрегатах).
- Интеграции с Health/Google Fit (возможный этап позже).
- Редактирование произвольного количества в прошлом дне (фокус на добавлении; правки прошлого не обязательны).

## Edge cases

| Ситуация | Ожидание |
|----------|----------|
| **Двойные тапы / быстрые клики** | Идемпотентность на уровне UI: debounce или блокировка кнопки на время записи; один пользовательский жест не должен создавать дубликаты без явного намерения. Store принимает последовательные `addSet` — каждый валидный клик создаёт отдельный `Set` с уникальным `id`; защита от случайного double-submit — на стороне feature. |
| **Смена календарного дня (полночь, timezone)** | «Сегодня» вычисляется по IANA timezone пользователя (store + `shared/lib`). При пересечении полночи главная и экран дня переключаются на новый день без перезагрузки страницы (тик / `visibilitychange` — см. хуки). |
| **Источник истины и localStorage** | **Доменные данные** (массив подходов, каталог типов, цели) — в **IndexedDB** через `StorageAdapter`. **localStorage** используется для **настроек и предпочтений клиента** (тема, часовой пояс, предпочитаемый тип упражнения и др.) — они не дублируют массив `Set`. При «очистке localStorage» в настройках доменные данные в IDB не трогаются, если не выбрана отдельная очистка БД. |
| **Пустые данные** | Нет подходов: пустой список, дружелюбный empty state, быстрые кнопки доступны (если есть активные типы). Статистика: нули или «—» для среднего/лучшего дня по правилам в `domain.md`. |
| **Повреждённое/частично прочитанное хранилище** | Ошибка чтения: сообщение в store (`lastError`), возможность сброса БД из настроек. Запись: откат оптимистичного обновления при ошибке. |
| **Очень большая история** | Сейчас полная загрузка `Set` в store при гидратации; при росте данных — возможна ленивая загрузка по диапазону (этап оптимизации). |
